# Principles

- Prefer a few clear task entrypoints with progressively disclosed domain resources over fragmented trigger overlap.
- Inspect before deciding: runtime truth outranks static inference.
- Search current upstream docs before choosing an extensibility pathway.
- Keep theme, Cart, Checkout, storage, CLI, and MCP capabilities independent.
- Use public WooCommerce and WordPress contracts, not internal modules, DOM structure, or direct order storage.
- Encode repeated detection and validation in deterministic scripts.
- Keep installed skills self-contained, symlink-free, and portable across supported assistants.
- Treat deprecated APIs as migration inputs, never silent fallbacks.
- Require scenarios and executable fixture tests for behavior that can be made deterministic.
